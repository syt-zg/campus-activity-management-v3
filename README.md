# 校园活动管理系统 V3.0

软件工程实验三《基于运行数据的需求演化》交付物。
在 V2.0（三角色、报名四状态、候补队列、审核、平台监管）基础上完成的一次有依据的迭代。

## 一、快速运行

**方式 A：直接用打包好的程序**

- 便携版：双击 `校园活动管理系统-便携版-3.0.0.exe`，无需安装。
- 安装版：双击 `校园活动管理系统-安装版-3.0.0.exe`，可选安装目录。

**方式 B：从源码运行**

```bash
# 在仓库根目录（含 package.json 的目录）执行
npm install
npm run start            # 等价于 node src/app.js，浏览器打开 http://127.0.0.1:3000
```

**默认账号**（初始密码均为 `123456`）

| 角色 | 账号 |
|---|---|
| 学生 | 2021001（陈小明）、2021002（刘小红） |
| 教师 | 10001 ～ 10010 |
| 管理员 | 90000 |

**运行数据位置**：桌面版在 Electron 的 userData 目录
（Windows 通常为 `%APPDATA%\校园活动管理系统\data`），含 `users.json`、`activities.json`、
V3.0 新增的 `events.jsonl`（运行事件流）、`messages.json`（系统主动通知）、`avatars.json` 与头像目录。
首次启动会复制 `data/` 下的示例数据，之后不再覆盖，卸载重装不清空。

## 二、这版解决了什么

V2.0 只保存**最终状态**，不保存**过程**：报名之后来没来、为什么退、名额是否被占住，系统都答不出来，
每轮改进只能依赖外部数据包。V3.0 分两轮推进：第一轮补齐过程数据与峰值稳定性，
第二轮按同一批数据扩展能力维度。

**第一轮：可观测与稳定性**

| 方向 | 具体改动 |
|---|---|
| 可观测 | 运行事件日志（`events.jsonl`）+ 管理员「运行统计」「运行日志」两个页面 |
| 补齐承诺 | 报名资格规则真正生效（V2.0 只存文本、从不校验）；活动删除改为归档，历史不再丢失 |
| 名额效率 | 递补确认窗口 + 超时自动释放顺延；取消原因留痕；出席（签到）记录 |
| 数据驱动 | 报名开放时间（错峰）、报名请求幂等、写入合并（60 并发 628ms → 223ms） |
| 教师效率 | 报名名单 CSV 导出、出席标记 |

**第二轮：能力扩展**（设计依据见 [`docs/V3-能力扩展设计.md`](docs/V3-能力扩展设计.md)）

| 方向 | 具体改动 | 数据依据 |
|---|---|---|
| 时间能力 | 学生「我的日程」周历、报名时冲突检测（拦截后确认可继续）、列表按星期与时段筛选 | 39.7% 的学生已存在时间重叠报名 |
| 系统主动性 | 规则引擎 + 心跳调度 + 消息中心，覆盖候补终局、候补临期、活动临近、供给不足四个节点 | 876 名候补者中 746 人（85.2%）无任何终态记录 |
| 供给侧分析 | 教师「活动效果」页：报名率、候补压力、出席率、取消率 + 扩容／调时段／维持建议 | 9 个组织者活动表现差异达数倍 |

## 三、怎么确认它真的有意义（可复跑）

```bash
node tests/v3-smoke.js        # 后端逻辑 51 项：资格、幂等、错峰、候补、递补、超时、出席、导出、统计、冲突、规则、建议
node tests/perf-compare.js    # 写入合并前后对比：同负载 3 轮，输出总耗时与落盘次数
node tests/ui-render.js http://127.0.0.1:3000   # 前端渲染 26 项（需先启动服务）
```

> 第三条测试依赖 `jsdom`（仅测试用，未写入 `package.json`）。
> 未安装时会提示跳过而不是报错；需要跑就 `npm i jsdom`，再设置
> `NODE_PATH=<该 node_modules 路径>` 即可。

实际输出见 [`docs/V3-VERIFY.md`](docs/V3-VERIFY.md)，未验证项也在里面列明。

## 六、边界说明

- 教师提供的模拟数据不是本系统产生的日志，只能作为需求判断依据；
  V3.0 的效果以 `tests/` 下三组测试为准，报告中已明确声明。
- 未纳入本轮：真实推送通道（校园环境无统一消息网关，站内消息中心已覆盖
  "不主动查看就收不到"的问题）、移动端适配、SQLite 迁移、统计大屏、列表分页。
  个性化推荐也未实现：402 名报过两个以上活动的学生中仅 6 人（1.5%）
  集中在单一活动类型，缺少稳定兴趣画像基础。理由见 `docs/V3-CHANGES.md` 的「实施边界」。
