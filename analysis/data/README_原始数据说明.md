# 校园活动管理系统 V2.0 模拟运行数据｜学生项目材料

## 使用说明
本压缩包提供统一模拟的 V2.0 平台运行样本，供软件工程实验三“从运行数据发现需求”使用。数据为教学目的构造，不包含真实学生个人信息，不是任一小组 V2.0 系统自动导出的日志。各小组应继续在自己的 V2.0 工程上迭代，不需要也不允许把本数据解释为本组软件真实生成的数据。

记录时间以北京时间（UTC+08:00）表达，主要覆盖 2026-09-21 至 2026-10-04；个别状态查询、取消及延迟行为记录可能超出该范围。日期均采用 YYYY-MM-DD HH:MM:SS，标识符为合成编号。

## 文件清单

| 文件 | 记录粒度 | 说明 |
|---|---|---|
| data/activity.csv | 每个活动一行 | 基本配置、类型、开放时间、容量等 |
| data/user_behavior.csv | 每次埋点事件一行 | 页面访问和用户行为；不是每个会话的完整路径保证 |
| data/registration_log.csv | 每次业务请求一行 | 报名与取消请求及处理结果、耗时 |
| data/waitlist_log.csv | 每次候补状态变化一行 | 可关联报名申请与状态演化 |
| data/feedback.csv | 每条匿名反馈一行 | 非结构化文本，不能直接当作所有用户的比例 |
| data/system_log.csv | 每条系统日志一行 | 包含业务请求相关与通用日志 |
| data/字段字典.csv | 每个字段一行 | 字段及代码值解释 |

## 数据使用边界
1. 数据是模拟的观察性材料，不能直接证明某个原因，也不能直接证明某个功能一定有效。
2. 记录分不同粒度，不可随意把“访问次数、申请次数、人数、活动数”混为一谈；统计比例时请注明分子、分母和筛选条件。
3. 不同表可通过 activity_id、student_id、request_id 或 application_id 关联，但需先确认关联业务含义与记录时间，不能默认一对一。
4. 允许使用 Python、Excel、数据库或其他工具分析。可采用适合本组分析方向的方法，关键结论应有可解释、可复核的依据。
5. 数据中存在少量采集重复、可空字段、无关日志和个别不完整观察链路；这些现象本身不直接构成产品需求。
6. V2.0→V3.0 的改进可根据所选需求采用适合的验证方式；涉及前后效果比较时，应尽可能保持比较条件一致。不能拿教师的历史模拟数据直接冒充 V3.0 的实测结果。

## 字符编码
CSV 为 UTF-8 with BOM，便于 Windows 系统、Excel 和 Python 读取。Python 示例读取参数可用 encoding='utf-8-sig'，这里只说明数据读取方式，不包含分析结论。
